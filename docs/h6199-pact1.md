## Encryption and setup

The [owner's response](https://github.com/teh-hippo/ha-govee-led-ble/issues/293#issuecomment-6128614924)
shows a successful encryption-information read containing exactly one byte,
`00`.  That complete marker permits plaintext independently of advertisement
availability.  Positive encryption evidence and a previously required encrypted
session still take precedence.  Empty/truncated markers, read errors and extra
bytes after `00` do not gain plaintext permission.

Setup uses the normal notification, identity, query and retry lifecycle.
Protocol diagnostics include the integration version, Pact, encryption evidence,
marker length and rejection class without addresses or unknown marker tails.
No guessed keepalive, `AA14` handshake or firmware change is introduced.
Camera silence cannot prevent ordinary lighting setup.

## State, uploads and recovery

Logical commands stay canonical; one shared transform encodes Pact 1 wire roots.
Effective profile selection reaches HA entities, services, Studio contracts,
catalogue limits, command expectations and status semantics.  The physical
writer rejects changed routing before encryption, optimism or transmission.

Complete RGB pages advance only colour observation.  Segment brightness is
omitted until genuinely known, with independent provenance.  Static reply
gradient is applied; its Kelvin candidate remains decode-only, not fresh
temperature evidence.  Restored and optimistic values never become observations.

Uploads require matching protocol/opcode ACKs before activation.  An A3 ACK
cannot release an A1 upload.  Cancelling a live edit prevents stale activation;
Studio live previews remain persistent edits, not a promise of automatic undo.
Explicit/deployment recovery uses only known, revision-compatible state.
Resident Studio selectors do not reveal their bodies or establish catalogue
identity.  Saved library/history data survives revision changes, while tagged
effect state prevents cross-revision cache matches or unsafe replay.

DreamView edits persist pending intent before BLE and keep prior authored
intent.  Final persistence must succeed before the new request is promoted.
Replacement/deletion do not automatically retry, replay or roll back after
uncertain delivery.  A group upload ACK means `acknowledged_unconfirmed`, never
observed membership; raw slot arrays are not mapped to authored identities.

## Owner qualification

An authorised exact-SHA model prerelease must be installed through HACS, followed
by a Home Assistant restart.  First confirm setup and inspect the reported Pact
and effective profile, then try ordinary lighting and Studio features.
Keep this candidate Experimental until visible behaviour, fresh readback and
recovery have been qualified.

After any failure, record the action, expected and actual result, Home Assistant
state and exact prerelease, then obtain immediate redacted diagnostics.
If setup never loads, provide only address-free protocol rejection lines with
debug logging enabled.  Do not publish Bluetooth addresses, serial numbers,
account details or an unredacted Home Assistant log.

Camera/video and destructive group edits need suitable hardware and an explicit
test agreement.  Unknown existing membership is not a restorable baseline.
Missing captures, owner Pact confirmation and physical results remain
qualification gaps, not proof that all candidate routes work.
